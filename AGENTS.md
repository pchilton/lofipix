# AGENTS.md — lofipix

Shared instructions for AI coding agents (Kilo Code, Hermes, and others) working in this repository. This file defines the durable rules.
Individual development tasks live in `prompts/` — an agent asked to "implement `prompts/NNNN`" reads this file first, then the prompt file.

## What this project is

lofipix is a multi-client app platform:

- **Web app** — SolidJS + Vite, static export (`www/`)
- **Mobile apps** — React Native (`mobile/android/`, `mobile/ios/`)
- **PWA** — SolidJS + Vite + VitePWA (`pwa/`)
- **Central API** — Fastify + Node.js + Drizzle ORM (`api/`)
- **Database** — PostgreSQL, schema + SQL migrations (`database/`)
- **Storage** — MinIO (S3-compatible) on local NVMe
- **Shared models** — Zod schemas + TypeScript types (`models/`)
- **Config / scripts** — `config/`, `scripts/`

Deployment: Docker Compose behind an nginx reverse proxy on a VPS. The README (`README.md`) is the single source of truth for architecture — consult it; do not duplicate it in prompts.

## Non-negotiables

1. **Verify before claiming done.** Run the project's typecheck/tests after changes and report the real output. Never report success from assumption.
2. **Keep the working tree clean.** Run `git status` before starting; commit related work in logical commits; never force-push or rewrite history.
3. **Conventional commits.** `feat:`, `fix:`, `chore:`, `docs:` etc.
4. **Database changes require a migration.** Never hand-edit the schema without a corresponding migration file in `database/`.
5. **Don't invent files or APIs.** If the README or a prompt references something that doesn't exist yet, create it as part of the task or flag the gap — don't silently substitute something else.
6. **Match the stack exactly.** TypeScript everywhere (no plain JS sources), Zod for shared validation, Drizzle for DB access. No alternative ORMs, frameworks, or validation libraries unless the prompt explicitly calls for them.

## Conventions

- Shared types and Zod schemas go in `models/` and are imported by API and clients — do not re-define them locally.
- API endpoints validate input with Zod schemas from `models/`.
- Object storage access goes through pre-signed URLs generated by the API — clients never hold S3 credentials.
- Config comes from `config/` + environment variables; no secrets committed to the repo.
- New top-level directories should be reflected in the README's directory table in the same change.

## Working with prompts/

- Tasks are numbered markdown files: `0001-<slug>.md`, `0002-<slug>.md`, …
- Each prompt contains: Context, Scope, Constraints, Definition of Done.
- Execute the Definition of Done checkboxes as literal acceptance criteria.
- If a prompt contradicts this file, the prompt wins for that task only — note the deviation in your report.
- When you complete a prompt, mark it completed (see `prompts/README.md`).
- Already completed prompts will have a suffix of `.done.md`, such as: `0001-<slug>.done.md`, `0002-<slug>.done.md`, …

## Reporting

When finished a task, report: what changed (files created/modified), what was verified (commands run + real results), and what is left or blocked. Do not re-narrate the process.
